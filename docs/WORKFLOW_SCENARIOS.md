# 연구 워크플로 사용 시나리오

이 문서는 UniPaper Bridge가 논문 요청을 받은 뒤 검색, 원문 확인, 근거 검증,
Zotero 보존, 결과물 출력까지 어떻게 이어 가는지를 실제 요청 예시로 설명합니다.

## 현재 기능과 계획 기능

시나리오에는 현재 0.5에서 사용할 수 있는 기능과 다음 릴리스에서 구현할
목표 기능이 함께 나옵니다. 계획 기능을 현재 제공되는 도구로 오해하지 않도록
아래처럼 구분합니다.

| 구분 | 기능 |
|---|---|
| 현재 0.5 | DOI·서지정보 확인, 제한된 인용 네트워크 확장, OA 검색, KHU 1회 1편 PDF 확보·검증·로컬 읽기·정리, Markdown·CSV 근거표, 로컬 문장별 인용 검증, 사용자 동의 기반 Zotero 저장 |
| 계획 | 체계적 문헌고찰 모드, Zotero 프로젝트 컬렉션, Excel·Word·BibTeX·RIS·LaTeX·PDF 통합 출력 |

## 시나리오 1: 논문 한 편을 찾아 달라는 요청

> GeoAI가 동아시아 도시연구에 적용된 대표 논문을 찾아줘.

1. Codex가 일반 학술검색으로 후보 논문을 찾습니다.
2. UniPaper Bridge가 DOI, 제목, 저자, 연도, 학술지 정보를 확인합니다.
3. 합법적으로 공개된 OA 원문을 먼저 찾습니다.
4. 실제 본문을 읽을 수 있을 때만 연구 질문, 방법, 데이터, 결과와 한계를
   원문 근거로 분석합니다.
5. 사용자가 Zotero 자동 저장에 동의했다면 최종 답변에 실제로 사용한 중요
   논문만 DOI 우선 중복 확인 후 저장합니다.

단순 요청에는 체계적 문헌고찰 절차나 PRISMA 수치를 적용하지 않습니다.

## 시나리오 2: 중요한 논문이 유료 원문인 경우

1. DOI와 서지정보를 먼저 확인합니다.
2. 저자 홈페이지, 기관 저장소, preprint 등 합법적인 OA 원문을 먼저 찾습니다.
3. 중요한 원문을 여전히 읽을 수 없을 때만 경희대 기관접속 브라우저를
   실행합니다.
4. 대학 계정은 운영체제 보안 저장소에서 격리된 로컬 헬퍼로만 전달됩니다.
   MCP와 모델에는 아이디, 비밀번호, 쿠키와 세션이 반환되지 않습니다.
5. 헬퍼가 출판사 페이지의 PDF를 자동으로 찾고 논문 1편만 임시 폴더에
   저장합니다. 자동 탐색이 안 되는 출판사에서는 같은 창의 PDF 버튼을
   사용자가 한 번 누를 수 있습니다.
6. 로컬 MCP가 PDF 서명·크기·해시를 확인하고, Codex가 필요한 페이지를
   최대 10쪽씩 읽어 원래 분석을 이어 갑니다. 사용자가 파일을 찾아 대화에
   첨부할 필요는 없습니다.
7. 허용된 Zotero 저장이 필요하면 검증된 임시 경로를 `licensed-pdf`로
   첨부한 다음 KHU 임시파일을 삭제합니다.
8. PDF를 확보하지 못하면 해당 논문은 `UNVERIFIED` 또는 메타데이터·초록
   한정 근거로 표시합니다.

브라우저가 열렸거나 파일 검증만 끝났다는 사실로 원문을 읽었다고 간주하지
않습니다. 본문 페이지를 실제로 확인한 뒤에만 `FULLTEXT-LICENSED`로
표시합니다. 공개 서버는 유료 PDF를 받지 않으며, 로컬 헬퍼도 일괄·백그라운드
다운로드나 재배포를 하지 않습니다.

## 시나리오 3: 여러 논문을 비교하는 요청

> 동아시아 도시의 폭염 취약성을 다룬 연구 15편을 비교해줘.

1. 일반 검색과 필요한 경우 한 단계 인용 네트워크 확장으로 후보를 찾습니다.
2. DOI와 정규화된 제목을 기준으로 중복을 제거합니다.
3. 각 논문의 접근 수준을 `FULLTEXT-OA`, `FULLTEXT-LICENSED`,
   `ABSTRACT-ONLY`, `METADATA-ONLY` 등으로 구분합니다.
4. 실제로 확인한 내용만 연구 지역, 기간, 데이터, 방법, 결과, 한계와
   페이지·절·표·그림 위치로 정리합니다.
5. `build_evidence_matrix`가 입력 근거를 검사하고 Markdown·CSV 비교표를
   생성합니다.
6. 근거가 부족하거나 위치가 없는 항목은 빈칸을 추측하지 않고 품질 경고로
   남깁니다.
7. 최종 분석에 사용한 중요 논문만 Zotero 저장 대상으로 선별합니다.

## 시나리오 4: 체계적 문헌고찰 요청 — 계획 기능

> 동아시아 도시 녹지가 노인의 정신건강에 미치는 영향을 체계적으로
> 검토해줘.

계획된 `run_systematic_review` 모드는 다음 순서로 작동합니다.

1. 연구 질문을 PICO 또는 SPIDER로 구조화합니다.
2. 동의어와 검색어 조합을 생성합니다.
3. 데이터베이스, 검색일과 실제 검색식을 기록합니다.
4. 검색 결과를 수집하고 중복을 제거합니다.
5. 사전에 정한 포함·제외 기준을 적용합니다.
6. 제외된 논문마다 사유를 기록합니다.
7. 제목, 초록, 원문 검토 단계의 PRISMA 흐름 수치를 생성합니다.
8. 최종 포함 논문만 원문 확보와 Zotero 저장 단계로 보냅니다.

일반 문헌조사에는 이 절차를 자동으로 붙이지 않습니다. 사용자가 체계적
문헌고찰을 요청하거나 재현 가능한 검토가 필요한 경우에만 별도 모드로
실행합니다.

## 시나리오 5: 논문 초안의 문장별 인용 검증

> 내 초안에서 인용이 제대로 된 건지 검사해줘.

1. Codex가 복합 문장을 검증 가능한 원자 주장으로 나눕니다.
2. 각 주장과 사용자가 제공한 원문 근거의 의미를 비교합니다.
3. 로컬 `audit_draft_claims`가 문장 오프셋, DOI, 접근 수준과 근거 위치를
   검증하고 다음 상태를 계산합니다.

   - `SUPPORTED`: 원문이 주장을 직접 뒷받침함
   - `PARTIAL`: 원문이 주장의 일부만 뒷받침함
   - `CONTRADICTED`: 원문이 주장과 충돌함
   - `UNVERIFIED`: 읽은 원문에서 확인하지 못함

4. 가능한 경우 DOI와 페이지·절·표·그림 위치를 함께 제시합니다.
5. 미공개 초안과 원문 내용은 로컬 검증 MCP 밖으로 전송하거나 저장하지
   않습니다.

예를 들어 초안이 모든 연령대에 효과가 있다고 주장하지만 원문이 노인
표본만 분석했다면 `PARTIAL`로 판정합니다.

## 시나리오 6: 논문들이 서로 반대 결과를 보이는 경우

1. 연구 대상, 지역, 기간, 표본, 측정 방법과 분석모형 차이를 비교합니다.
2. 각 결론을 지지하거나 반박하는 정확한 원문 위치를 나눠 기록합니다.
3. 다수결로 하나의 결론을 만들지 않고 근거가 일관된 부분과 충돌하는
   부분을 분리합니다.
4. 현재 근거로 확정할 수 없는 부분은 잠정 결론 또는 `UNVERIFIED`로
   표시합니다.
5. 사용자가 Zotero 저장에 동의했다면 최종 판단에 중요한 반박 논문도
   보존합니다.

## 시나리오 7: 결과물을 여러 형식으로 내보내는 요청 — 계획 기능

> 비교표는 Excel, 문헌검토는 Word, 참고문헌은 BibTeX, 검증 결과는 PDF로
> 줘.

계획된 출력 기능은 하나의 검증된 `ResearchBundle`에서 사용자가 요청한
파일만 생성합니다.

| 내용 | 출력 형식 |
|---|---|
| 다중 논문 비교표 | CSV, Excel |
| 참고문헌 | BibTeX, RIS |
| 문헌검토 | Word, Markdown |
| 논문 초안 | LaTeX와 BibTeX 묶음 |
| 문장별 검증 보고서 | PDF |

모든 출력물이 동일한 DOI, 접근 라벨과 근거 위치를 사용하도록 하며,
`export_manifest.json`에 생성 성공 여부와 누락 원문·미검증 주장 등의 경고를
기록할 계획입니다. 현재 0.5는 근거표의 Markdown·CSV 출력을 제공합니다.

## 시나리오 8: 후배가 다른 운영체제에서 사용하는 경우

1. 각 사용자가 GitHub 저장소를 자신의 컴퓨터에 clone하고 빌드합니다.
2. 플러그인과 로컬 MCP를 설치합니다.
3. 각자 자신의 대학 계정을 자기 컴퓨터의 보안 저장소에 등록합니다.
4. macOS는 Keychain, Windows는 현재 사용자 범위 DPAPI, Linux 데스크톱은
   Secret Service를 사용합니다.
5. 계정, 비밀번호, 브라우저 프로필과 세션은 GitHub로 공유하지 않습니다.
6. 각자 자신의 Zotero 라이브러리에서 저장 동의 여부를 설정합니다.

즉, 연구 워크플로 코드는 공유하지만 자격증명과 유료 원문은 공유하지
않습니다. 운영체제별 설치 과정은 [로컬 설치 안내](../local/INSTALL-KO.md)를
따르세요.

## 항상 지키는 원칙

- 일반 학술검색과 OA 원문 확인이 항상 먼저입니다.
- 대학 기관접속은 중요한 원문을 읽을 수 없을 때만 사용합니다.
- 실제로 읽지 않은 원문은 읽었다고 표시하지 않습니다.
- 검색 결과 전체가 아니라 최종 판단에 중요한 논문만 Zotero에 저장합니다.
- 사용자 자격증명, 세션, 미공개 초안과 유료 PDF는 공개 MCP나 GitHub에
  올리지 않습니다.
